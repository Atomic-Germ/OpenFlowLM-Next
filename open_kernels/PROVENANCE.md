## What this is

Open AIE kernels for XDNA2 (AMD Ryzen AI NPU), written with the IRON / mlir-aie
toolchain. 21 designs covering every op in a Qwen3.6-MoE decode step: q4_1 GEMV
with dequant fused into the integer matrix unit, q8 lm_head, gated DeltaNet,
conv1d / SiLU / q-k norm glue, RMSNorm + residual, full attention with dynamic
KV, MoE router with on-device top-8, and the fused whole-layer designs
(`designs/layer_x/`). `README.md` is the status table and the XDNA2 trap
catalogue — read it before editing any design.

## What was deliberately not copied

- `designs/*/build*/` — compiled `final.xclbin` / `insts.bin` / `insts.elf`.
  Gitignored upstream; rebuild with `build_design.py`. They are still on Cyrus's
  machine if a known-good binary is wanted to test a dispatcher against.
- `*.bin` test fixtures and reference vectors — regenerated by each design's
  `make_test.py`. Several of those slice weights out of buffers captured from
  OFLM's closed engine (phlegm's `C:/caps` tree), which are not in this repo:
  they take the capture directory from `OPEN_KERNELS_CAPS` and stop with a
  message when it is unset (`fixture_paths.py`). `gemv_q4`, `ln`, `silu_mul`
  and `npu_offload/matmul` have synthetic fixtures and need nothing.
- The `*_chain/make_*.py` harnesses additionally import phlegm's
  `tools/kernel-interp` (`PHLEGM_KERNEL_INTERP`) and a model container
  (`MODEL_Q4NX`). They are phlegm's step-by-step chains, kept for the record;
  `model/` (`replica.py`, `make_decode.py`) is the in-repo way to score the
  kernels against an fp64 reference.
- `run*.cfg` driver configs and `*.log` run records — generated. Every path a
  generated cfg names is relative to the design directory (`run_kernel`
  resolves against the cfg's own directory).

## Toolchain

Built against **mlir-aie 1.4.2** + Peano (llvm-aie 21.0.0). These designs use the
1.4.2 IRON runtime API (free-standing `TaskGroup()`, `fifo.fill(...)`,
`tg.finish()`) and will **not** run on 1.3.4, which puts those on `Runtime`
(`rt.task_group()`, `rt.fill(fifo, ...)`, `rt.finish_task_group(tg)`). See
`.claude/plans/phlegm-open-kernels-adoption.md`.

## Added in this tree (not from phlegm)

- `harness/` — `run_kernel` (C++, XRT) plus `build.cmd` / `CMakeLists.txt` /
  `bench.py`. Optional target `OFLM_BUILD_OPEN_KERNELS_HARNESS` in `src/`.
- `q4_1_pack.py` — GGUF Q4_1 blocks → pool-order chunks (the packer seed) with a
  self-test.
- `designs/gemv_q4/make_test.py`, `designs/ln/make_test.py` — synthetic fixtures
  by default (`--source captured` / `--captured` keep phlegm's originals);
  relative paths in the generated cfg.
- `designs/lm_head_q8/make_test.py` — relative paths, `LMHEAD_POOL` override
  (still needs a captured pool; no synthetic Q8_0 path yet).
- `fixture_paths.py` — the one place the generators get capture / kernel-interp
  / model paths from (environment, with a clear error), replacing phlegm's
  hard-coded `C:/caps` and `C:/code/phlegm` paths in every `make_*.py`.
- `export_qwen36_kernels.py` — builds the six kernel sets the engine loads
  (`lx0 lx1 ax0 ax1 ln lm_head_q8`) into `src/xclbins/<model>/open_kernels/`
  with a `toolchain.json`, and checks a rebuild against a previous one. The
  compiled kernels are not checked in (see `.gitignore`); this is how they are
  made. Details in `src/open_qwen36/README.md`.

- `designs/gemm_q4/` — the batched prefill GEMM, written after the snapshot
  above and brought in on 2026-09-15. `gemv_q4` with an M dimension: one weight
  pass feeds M tokens, which is what makes prefill compute-bound instead of
  bandwidth-bound. Eats Q4_K chunks as stored (no requantisation) by folding the
  6-bit sub-scales into the integer accumulation, and streams an activation
  table the host has already quantised, so the core does no prep arithmetic.
  Adapted on the way in: cfg paths are relative to the design directory, per
  `fixture_paths.py`, and the fixtures (`w_*.bin`, `x_*.bin`, `ref_q4k.bin`)
  are generated by `make_q4k.py` / `make_test.py` / `prep_host.py` rather than
  checked in.

- `designs/whisper_gemm/` — the Whisper encoder's seven GEMM streams, brought in
  as part of the open Whisper engine (issue #72); see its own `README.md`.

- `designs/whisper_fa/` — the Whisper encoder's bidirectional FlashAttention,
  brought in 2026-09-24.
  - `attn_npu2.cc` (the compute kernels) is **derived from Xilinx/mlir-air**
    (https://github.com/Xilinx/mlir-air, commit `e91630a`),
    `programming_examples/flash_attention/kernel_fusion_based/attn_npu2.cc`, MIT,
    Copyright (C) 2025 Advanced Micro Devices, Inc. — **modified**: a key-length
    mask, an fp32 online-softmax running sum, and a software exp2 polynomial
    taken from **mlir-aie**'s `aie_kernels/aie2p/exp2f_vec.cc` (Apache-2.0 WITH
    LLVM-exception, Copyright (C) 2026 AMD; attributed at the point of use). The
    file's header lists every change.
  - `zero.cc` (zero / neg-inf fill helpers): from the same mlir-air example, MIT,
    unmodified apart from a header note.
  - `attn_fa.py` (the IRON design) and `attn_cascade_wrap.cc` (the cascade-port
    transfers IRON's `CascadeFlow` needs, which AIR's compiler otherwise emits
    inline) are ours: an IRON (mlir-aie) port of AMD's MLIR-AIR design, built by
    our pinned toolchain rather than MLIR-AIR's, done in the sibling
    `NpuEmbeddings` repository's `tasks/0181-fa-iron-port/`. Verified
    byte-identical, at production shape, to AMD's own design compiled by the same
    toolchain, on real Whisper layers 0/15/31.
